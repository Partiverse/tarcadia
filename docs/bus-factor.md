# 桃花源（Tarcadia）团队单点风险预案 v0.1

> 版本 v0.1 · 2026-10-03 · 上游：`production-scope.md` §9（4–5 人分工）、`feasibility.md`（B 档模型）。
> 诚实的定义：小团队的"bus factor"实际很少是车祸，**实际形态是：主创 burnout、被挖角、家庭变故、和外包供应商跑路的混合体**。本表按"该人/该供应商失联 8 周"统一评估。目标线：**任何单点失联，最近的一个里程碑门（M9/M12/M15/M18）最多顺延 4 周，不判死**。

## 3. 写进纪律的四条（零成本，从 M6 起生效）

1. **文档即交接**：任何"只有某人知道"的系统决定，视同 bug——周报 30 分钟回写，PR 不带文档回写不合并。
2. **runbook 优先于口传**：内容三件套（加作物/加 NPC/加事件）在 M9 前必须存在且由非作者跑通一次。
3. **可整包外判的切分是设计义务**：新内容规划时自问"这块能不能哪天扔给陌生人续"——闲话池/声景分组/glossary 都已按此形状长。
4. **降级预案永远比单点低一级**：照 production-scope §7 瓶颈声明/§12 风险登记的格式，每个已批准决策注明降级动作，主创缺席时团队照表执行而非等拍板。

## 4. 考据公共簿（backlog，M7 起滚动）

`docs/research-notes/`（暂不建目录，防文档链虚胖）：节气农谚出处、傩戏素材版权、三线厂口述来源、方言虚词表——每条一句"来源+可信度+可否直接使用"。主责文案；**缺失不阻塞 EA**（阻塞的是审核安全和"不悬浮"外部审读，narrative §11 已挂钩）。
